# 可回馈上游的优化清单（暂不提交 issue）

评估日期 2026-09-14 · 对照上游 rc.8 (209c0f6)

本清单按**可回馈性**分级：是否自包含、是否需要额外安装、是否有行为变更。
所有数字均为实机实测。

---

## 级别 A：纯缺陷修复，无行为变更，可独立提交

### A1. tap 纵向漂移 35px —— **最值得回馈**

**上游确实存在此 bug**（已核对上游源码）：

```ts
// tool-uitree.ts 上游第 784 行
const tap = { x: center.x / screen.width, y: center.y / screen.height }

// android-host.ts 上游第 533 行 #pixels
{ x: Math.round(x * frame.width), y: Math.round(y * frame.height) }
```

两处**假定同一个分母**：前者用 UI 树的高度（app 帧，实测 1500），
后者用实时帧高度（完整显示区，实测 1536）。缩放系数 1536/1500 = 1.024，
**屏幕越靠下偏移越大**：

| 目标 y | 实际落点 | 漂移 |
|---:|---:|---:|
| 132 | 135 | +3 px |
| 838 | 858 | +20 px |
| 1450 | 1485 | **+35 px** |

**后果**：靠近屏幕底部的控件**点不中**（落到系统手势条被吞）。
真机上表现为「点了没反应」——我实测安装按钮时正是如此。

**修复方式**（本 fork 已实现）：

- 新增 `treePixelToInput(pixel, input, round)`：**不缩放像素**（两空间共享原点），
  只用 input 空间做分母
- host 暴露 `inputSpace(serial)`，与 `#pixels` **同源**，杜绝再次分叉
- 另修：`inputSpace` 回退到 `wm size` 时**不感知旋转**，横屏会轴对调

**改动面**：`android-host.ts` +17、`tool-uitree.ts` +19、`tool-list-rows.ts` +12、`uitree.ts` +46
**自包含**：是（不依赖 bridge）
**行为变更**：有——但那是**修正**（把点不中变成点得中）

### A2. 图像链路静默失效

`resolveVisionServices(ctx)` 在 `apply()` 时**急切采样并缓存**，而 cordis 的
`ctx.get(name)` 默认 `strict=true`，只在提供方 fiber 处于 active 时返回服务。
`attachments` 是可选服务，无权保证先激活 → 抢跑就把 `{}` **冻结一辈子**。

**叠加第二个 bug**：守卫只检查 `saveImage`，而挂载的 `LocalAttachmentStore`
同时有 `saveImages`（文档化的批量入口）。

**后果**：截图工具**从未真正把图交给模型**，且**完全静默**（无错误、无日志，
看起来和文本路由一模一样）。

**修复**：惰性 getter 每次重读 + 接受任一入口。

**改动面**：`vision.ts` +80 −6
**自包含**：是
**行为变更**：有——从「静默不工作」变成「真的工作」

---

### A3. `if_moved` 的指纹记账时机

`android_ui_tree` **每次读取都记一次屏幕指纹**（完整 `dumpsys window`，实测 ~150 ms），
目的是让**后续**的 `if_moved` 读取能证明屏幕没变。
但从不传 `if_moved` 的调用方**每次都在为一个自己用不上的缓存付费**。

**修复**：按需记录（只在 `if_moved: true` 时记）。

**实测收益**：`android_ui_tree` p50 **194 ms → 40 ms**（bridge 关闭时）。

**改动面**：`tool-uitree.ts` 约 10 行
**自包含**：是（前提是上游先接受 `if_moved`，即 ~ed2f6a9 那一串）

## 级别 B：性能优化，自包含，无行为变更

### B1. 直连 adb server 枚举设备（省 59 ms → 1 ms）

`resolveTarget()` 每次工具调用都 spawn 一次 `adb devices -l`。

**关键实测**：

| 命令 | 耗时 |
|---|---:|
| `adb version`（仅 spawn + 握手，不查设备）| **51 ms** |
| `adb devices -l` | 59 ms |

**枚举本身只要 6 ms，51 ms 全是启动进程**。所以缓存结果没用；必须不启动进程。

**实现**：跟 adb server（`127.0.0.1:5037`）直接说长度前缀协议，
`host:devices-l` 实测 **0–1 ms**，输出与 CLI **逐字节相同**
（只少 CLI 自己那行表头，上游解析器本来就跳过）。

**改动面**：新增 `adb-server.ts`（142 行，无依赖）+ `adb.ts`、`android-host.ts` 接线
**自包含**：是
**行为变更**：无（失败即回退 CLI）

**注意**：这是唯一需要 **新增文件** 的候选，且属于绕过官方 CLI；
adb 协议二十年未变，但理论上存在风险。

---

### B2. 用 stream 状态回答设备查询

正在跑的 frame loop 本身就是「设备在线」的证据，可完全跳过查询。
**故意做窄**：只在调用方指名了确切 serial 且 loop 正在跑时生效，
设备中途掉线仍走真实查询。

**改动面**：`android-host.ts` +25
**自包含**：是
**行为变更**：无

---

### B3. dump 与 screencap 并行

两者**完全独立**（dump 走无障碍，截图走 display surface），但一直顺序 await。

**实测**：顺序 2768 ms → 并行 2394 ms，**省 374 ms（13.5%）**。

**改动面**：小
**自包含**：是
**注意**：仅在有工具同时需要两者时才有收益；上游目前没有这样的工具。

## 级别 C：需要设计讨论，不宜直接提交

### C1. `view: "actionable"`（省 56–59% token）

新增可选参数，**默认行为逐字节不变**（本 fork 有 5 条契约测试锁定）。

**为什么仍算 C**：它是**新增能力**而非修复，涉及 API 表面决策。
上游可能对「再加一个视图模式」有不同意见。

**改动面**：`tool-uitree.ts` +167、`uitree.ts` +152

### C2. 静默截断 → 降采样 + 报告

上游超出 40 KB 时**整层删除最深节点**（最具体的控件），
返回一棵**看起来完整**的树。

**为什么算 C**：改变输出的**语义**（从「完整但可能被裁」变成「明确的样本」），
可能影响依赖现有行为的调用方。

### C3. 常驻桥接（bridge，2.4 s → 4 ms）

**不可直接回馈**：需要在设备上安装 APK 并授权，
与上游「纯 adb、零安装」的设计哲学**背离**。

但可以作为一个**可选扩展**提议，前提是上游接受「可选组件」这一前提。

| 顺序 | 项 | 理由 |

| 1 | **A1 tap 漂移** | 上游真实缺陷，影响每次点击，修复自包含 |
| 2 | **A2 图像链路** | 静默失效最危险，修复小 |
| 3 | **A3 指纹记账** | 小改动，立竿见影（省 150 ms/次）|

| 5 | **B2 stream 快捷路径** | 锦上添花 |
| — | C1/C2/C3 | 需先与维护者讨论方向 |
