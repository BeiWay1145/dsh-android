# 最终延迟评测

2026-09-14 · 小米平板5（M2105K81AC, Android 13, MIUI 14）· 竖屏 1536x2560

## 一、原始路径（不含工具层）

n=12-30，单位 ms。

| 路径 | min | p50 | max |
|---|---:|---:|---:|
| bridge（热，socket 往返） | 2 | **4** | 7 |
| uiautomator dump | 3242 | **3571** | 4122 |

**原始路径约 890 倍。**

bridge 的 4ms 里已经包含：socket 往返 + 无障碍树遍历 + XML 序列化 + JSON 转义。
也就是说，**真正的「读一屏」成本就是几毫秒**；原来的 3.5 秒几乎全是
每次重新启动 JVM（0.51s）与加载类（1.16s）外加 uiautomator 自身开销。

## 二、工具层（android_ui_tree，端到端）

| 版本 | p50 | 相对 uiautomator |
|---|---:|---:|
| uiautomator 回退路径 | 3998 ms | 1x |
| bridge（修复前） | 194 ms | 20.8x |
| **bridge（修复后）** | **40 ms** | **90.9x** |

n=30 稳定性（修复后）：

    min/p50/p90/max = 35 / 40 / 55 / 107 ms
    mean 44 ms, stdev 14 ms

## 三、194ms → 40ms 是怎么来的

测量时发现工具层比原始路径慢 190ms，逐项归因后定位到：

**`android_ui_tree` 每次 dump 后都记一次屏幕指纹**（完整 `dumpsys window` 往返，
约 150ms），目的是让**后续**的 `if_moved` 读取能证明屏幕没变。

问题是这个指纹**无条件记录** —— 从不传 `if_moved` 的调用方，
每次读取都为一个自己用不上的缓存付费。

改为**按需记录**（只在 `if_moved: true` 时记）后：

| | 修复前 | 修复后 |
|---|---:|---:|
| android_ui_tree p50 | 194 ms | **40 ms** |
| 相对 uiautomator | 20.8x | **90.9x** |

`if_moved` 功能未受影响（已验证：第二次 `if_moved` 读取仍报 `cached: true`，
普通读取不报 `cached`）。

## 四、方案2 的增量（空闲屏）

设备端 revision 计数器，内容未变时**不传输 XML**：

| | 耗时 |
|---|---:|
| 首次读取（真 dump） | 56 ms |
| 空闲屏重复读取 | **2-4 ms** |

dump 与 screencap 并行（两者互不依赖）：

| | 实测 |
|---|---:|
| 顺序 | 2768 ms |
| 并行 | 2394 ms |
| **节省** | **374 ms（13.5%）** |

## 六、综合评价

### 量级判断

| 场景 | 改善 | 量级 |
|---|---|---|
| 原始读屏 | 3571 → 4 ms | **约 3 个数量级** |
| 工具端到端 | 3998 → 40 ms | **约 2 个数量级（91x）** |
| 空闲屏重复读 | — → 2-4 ms | 接近免费 |
| tap 落点精度 | 35px 漂移 → 0 | 从「点不中」到「点得准」 |

### 这意味着什么

1. **agent 的读屏操作从「昂贵动作」变成「廉价动作」。**
   40ms 与人眼一次的间隔同量级，agent 可以在一次推理里多次确认屏幕，
   而不是每次都要为 4 秒做权衡。

2. **单次会话的累积收益远大于单次数字。**
   典型的 UI 任务要读屏 10-30 次；按 20 次算，
   3.998s × 20 = 80 秒 → 0.04s × 20 = 0.8 秒，**省约 79 秒**。

3. **推理成本同时下降。** 方案2 未变时不传 XML，
   省的不只是时间还有 token（树体量 10-200KB）。

### 边界（诚实说明）

- 以上是**本机 + 该设备**的实测，不代表所有机型；
  低端机、模拟器、其他厂商 ROM 的绝对数字会不同，但量级关系应当保持。
- 工具层 40ms 里仍有约 29ms 是 `adb devices`（`resolveTarget` 每次调用），
  这是**既有开销**，与 bridge 无关，仍有优化空间。
- bridge 需要装 APK + 授权；**不装则完全回到原路径**，只是慢。
