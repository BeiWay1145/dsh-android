# token 成本实测

2026-09-14 · 小米平板5，同一块屏幕

## 三条路径的真实成本

| 路径 | 载荷 | ≈tokens | 完整度 |
|---|---:|---:|---|
| android_ui_tree（全量） | 36,144 B | **~10,300** | 截断 |
| android_ui_rows | 3,660 B | **~1,046** | 完整 |
| 图片（screencap → 附件） | 19 KB PNG / 2560x1536 | **~1,970-2,635** | 完整 |

图片 token 按两种主流计费公式估算：

- OpenAI 式 512px 分块：3x5=15 块，15*170+85 = **2,635**
- Anthropic 式 (w*h)/750：3.93MP/750 = **5,243**（原尺寸）
- 长边压到 1568px 后：(941*1568)/750 = **1,967**

## 结论：图片并不贵

**这推翻了我原本的假设。** 我之前以为图片按视觉 token 计费会很贵，
实测表明图片比全量 ui_tree **便宜 3-5 倍**。

排序（同一屏，从便宜到贵）：

    android_ui_rows  ~1,050 tokens   最便宜，且完整
    图片             ~2,000-2,600    完整，可读任意界面
    android_ui_tree  ~10,300 tokens  最贵，且会截断

## 实用含义

1. **ui_rows 仍是首选** —— 最便宜且完整
2. **图片是合理的次选** —— 对 Compose/Flutter/WebView 这类
   无障碍树稀疏的界面，图片往往**又便宜又有效**（树可能是空的）
3. **ui_tree 应当是最后手段** —— 它同时是最贵的**和**最不完整的

## 注意

- token 估算基于公开公式，**不是对当前路由的实测计费**；
  实际取决于 harness 是否压缩、以及所用模型的分词方式
- PNG 只有 19 KB 是因为截的是深色纯色界面；复杂界面会更大
  （但图片 token 由**像素**决定，不由文件大小决定）
